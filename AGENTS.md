# Development instructions

- Keep pi-agentlet minimal: bounded, blocking delegation to independent pi sessions, with final-only results and no orchestration framework. Read `docs/functional-spec.md` for the current product contract and `docs/architecture.md` for design decisions; consult `docs/compatibility.md` for host-specific boundaries. Write code, comments, tests, and documentation in English.
- Architecture: root `index.ts` re-exports the extension; `src/index.ts` registers the tool/lifecycle; `manager.ts` owns the shared queue and aggregation; `runner.ts`, `protocol.ts`, and `process-tree.ts` own subprocesses, JSONL, and cleanup; `resources.ts` and `verify-child.ts` reconstruct/check configuration; `results.ts` owns final-only output/artifacts; `ui.ts` renders the ordinary tool block. Limits live in `limits.ts`.
- Run `npm test`, `npm run typecheck`, and `npm run check`. Reuse an existing compiler/host with `PI_AGENTLET_TYPESCRIPT` and `PI_AGENTLET_HOST` if dependencies are not local. See `docs/development.md`. Never install software or invoke a paid provider implicitly.
- The optional `PI_AGENTLET_CLI=... node scripts/smoke.mjs` checks a real local pi with a deterministic offline provider. Standard tests must remain network-, credential-, and global-installation-independent.
- Use strict, erasable TypeScript and Node built-ins. Keep host packages as `*` peer dependencies. Do not bundle another pi runtime or add queue/process/UI libraries unnecessarily.
- Before changing integration, read the installed pi version's extension, JSON, SDK/resource, lifecycle, package, and TUI documentation in full and inspect corresponding public types/examples. Compatibility is deliberately pinned to the reviewed version.
- Never copy/fork parent conversation history, dump child transcripts/thinking into results, or deliver results later through `sendMessage`. Progress belongs in compact `details`, not model-visible content.
- Preserve applicable resources, tool restrictions, effective model/thinking, cwd, configuration directory, and temporary project trust. No silent fallback, automatic trust approvals, startup installations, or loss of extensions/skills for convenience. Incompatible runtime-only configuration must fail clearly.
- Do not technically disable `subagents` in children. The prohibition on further delegation is an instruction, not an enforcement mechanism. This AGENTS.md is repository guidance, not the child delegation prompt.
- No workflows, personas, pipelines, daemons, durable job registry, worktrees, or custom management panels without an explicitly approved scope change.
- Subprocess tasks go through stdin with `shell: false`. Bound buffers, avoid credential/raw error logging, keep private final-answer artifacts outside the repository, and retain returned artifacts until user/OS cleanup.
- Cancellation and timeout must settle exactly once, terminate descendants, escalate if necessary, remove listeners/timers, await actual close, and prevent progress after teardown. Test races, failures, UTF-8 framing, and cross-call concurrency.
- Keep README, functional specification, architecture decisions, compatibility notes, tests, and approved product behavior consistent. Discuss central API blockers before replacing requirements with incompatible alternatives.
